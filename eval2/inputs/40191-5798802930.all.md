## Description
Zulip uses "URL" rather than the deprecated "URI" (#23380), so this renames the `DEFAULT_AVATAR_URI` and `DEFAULT_LOGO_URI` server settings to `DEFAULT_AVATAR_URL` and `DEFAULT_LOGO_URL`, one commit per setting.

Servers upgrading from an older release may still set the old names in `/etc/zulip/settings.py`. To keep those working, `computed_settings.py` copies the old value into the new setting when only the old one is set, like the Google OAuth settings fallback there. The rest of the code reads only the new names.

The third commit adds a system check (`zulip.E008`) for a server that sets both names to different values, where the old one would otherwise be silently ignored. It's separate so it can be dropped.

Fixes: part of #23380. The Home Assistant docs fix that was first in this PR is now #40197.

**How changes were tested:**

- `test_server_settings.py`: new tests reload `computed_settings` to check that the old name is used when the new one is unset, and that the new one wins when both are set.
- `test_upload.py`: the default avatar, realm icon and realm logo tests now set the new names.
- `test_checks.py`: the check reports both settings (including the Docker wording), and stays quiet when only one name is set.

### #23380 (issue, open): Stop using the deprecated "uri" terminology in favor of "url"
Opened by timabbott (MEMBER). Labels: help wanted, area: refactoring, in progress. Assignees: Aditya-XR.
Description: We should stop using the deprecated "uri" abbreviation in favor of "url". There's some complicated history for the terminology in general touched on in https://github.com/zulip/zulip-mobile/blob/main/docs/style.md#url-not-uri. 

This is a very rough way to investigate how we we use these in the web app; not a huge number of references in the server codebase (though there's a lot more in templates and the like).

```
(zulip-py3-venv) tabbott@coset:~/zulip$ git grep _uri zerver/ | wc
    105     410    9316
(zulip-py3-venv) tabbott@coset:~/zulip$ git grep [.]uri zerver/ | wc
     89     381    8161
```

The vast majority of these will be things we can just change, though we should do this thoughtfully in a reviewable way, with one commit per thing. For example, renaming `encode_zuliprc_as_uri` should be a single commit that changes all references to that variable.

The one thing that will hard will be this line: `zerver/lib/events.py:        state["realm_uri"] = realm.uri`, which is an API change; we should save that for last (as it'll likely require adding a new `realm_url`, leaving the old name available for mobile clients and other API tools that we don't want to break compatibility for), after we've renamed all the smaller uses that don't require this API change.
