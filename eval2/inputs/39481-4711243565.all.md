## Description
Fixes #19589.

This PR separates the `command` and `text` fields when parsing Slack-compatible outgoing webhooks. This ensures that the command correctly receives the triggered keyword, while the text field receives the remaining message payload.

I started this PR from scratch and did not use the work from PR #38098, as my approach directly handles the separation logic in the core event parser and I wanted to add more comprehensive unit testing for both the mention formatting and standard text payloads.

**Testing:**
- Manually tested by sending webhooks with separate command and text payloads.
- Updated and ran unit tests in `zerver/tests/test_outgoing_webhook_interfaces.py` to assert the correct splitting of fields.

### #38098 (PR, closed): outgoing webhooks: Parse bot mentions into 'command' field for Slack. Fixes #19589
Opened by KumarManuSaraswat (COLLABORATOR). Labels: area: integrations, good first issue, size: M, maintainer review. Assignees: Niloth-p.
Description: **Description**
When a message triggers an outgoing webhook starting with a bot mention, Slack expects the bot mention to be sent as a slash command in a separate `command` field, and the rest of the message in the `text` field. 

Previously, Zulip was sending the raw markdown (e.g., `@**botname** some text`) entirely within the `text` field, which broke compatibility with external services expecting the Slack format.

This PR updates `SlackOutgoingWebhookService` to:
1. Parse the mention from the start of the message using regex.
2. Transform the bot name into a slash command (e.g., `/botname`) and place it in a new `command` field.
3. Place the remainder of the string into the `text` field.
