## Description
Prettified channel/topic/message link syntax (`#**stream**` and its `>topic`/`@message_id` variants) is meant to render as its own link. But StreamPattern, StreamTopicPattern, and StreamTopicMessagePattern run at a higher inline-processor priority than the generic Markdown LinkInlineProcessor, and their "start of match" guard regex also allows matching right after `(`. So when this syntax was pasted into the URL placeholder of ordinary hyperlink syntax, e.g. `[my link](#**stream**)`, it got converted into a nested `<a>` element before the outer link syntax was considered, silently breaking the link's href.

Detect this case (immediately preceded by `](`) in each pattern's handleMatch and return the resolved narrow URL as plain text instead of building an element, so the lower-priority LinkInlineProcessor renders the outer `[label](url)` link correctly afterwards.

Related issue: #31985.

### #31985 (issue, open): Pasting channel links into markdown can silently fail
Opened by jmandel (CONTRIBUTOR). Labels: bug, area: compose (misc), priority: high, help wanted, in progress. Assignees: PrinceXDev.
Description: This relates to https://github.com/zulip/zulip/issues/31813, where "Copy link to channel" produces a plaintext link and a markdown snippet. The issue is that a user will see inconsistent behavior when pasting this link into their own markdown.

Say a user clicks "Copy link to channel" and then pastes to compose a message like https://chat.fhir.org/#narrow/stream/179240-Announcements/topic/SQL.20on.20FHIR.20Conference/near/476586725, including:

```markdown
... The SQL on FHIR conference is a community event hosted by the [SQL on FHIR](#**analytics on FHIR**) group which is a FHIR Foundation project
```

This looks fine when rendered:
![image](https://github.com/user-attachments/assets/867220f5-fc88-4cf7-af38-d4de354b4e3a)

But in fact the "SQL on FHIR" text is a broken link to `https://chat.fhir.org/#analytics%20on%20FHIR`

Possible solutions:

1. Revise https://github.com/zulip/zulip/issues/31813 to only copy a link, and not a `**Channel Name**` snippet -- this is arguably the least surprising behavior given the menu item is called "Copy link to channel", and avoids subtle issues like the one encountered here.
2. Ensure that `**Channel Name**` syntax is correctly expanded in `[Alias For Channel](**Channel Name**)` markdown snippets
