## Description
This PR updates bot avatar upload behavior in the bot management modal to match user profile picture uploads: hover to upload/delete, Uppy editor cropping, and immediate save without clicking `Save changes`.

It builds on the Work in Progress PR in [#38032](https://github.com/zulip/zulip/pull/38032), which introduced the shared `image_upload_widget` function and direct-upload path for bot avatars. That PR had not implemented functionality for deleting the avatar, which now exists without creating a new endpoint (using existing `patch_bot_backend`). It also closed the entire bot management modal after saving the cropped image, which I believe wasn't the intended behavior, so I updated it to save the avatar immediately after cropping but keeping the management modal open. Deleting the user-uploaded avatar resets the bot avatar to either the gravatar or Jdenticon, which may be related to #24427 as well. 

Here's the discussion: [#api design > Bot avatar management (#40013)](https://chat.zulip.org/#narrow/channel/378-api-design/topic/Bot.20avatar.20management.20.28.2340013.29/with/2524187) for the API Design feedback. 

Fixes: #29766 

**Possible remaining work**:
- Asked in [#design > editing bot avatar @ 💬](https://chat.zulip.org/#narrow/channel/101-design/topic/editing.20bot.20avatar/near/2512161) regarding tooltips. Waiting to hear for more feedback if there's still need for tooltips when hovering over the bot avatar since this implementation displays text on hover. Currently have one go-ahead.
- If desired, could scroll to avatar view after the changes with the croppy editor. The behavior from the PR's changes: after saving changes inside the uppy editor, the bot avatar is saved and the management modal is reopened but not scrolled down. Scrolling to view after the changes _could_ provide better UX by showing users the bot avatar right after they confirmed the cropped image, althought it may not be necessary.
