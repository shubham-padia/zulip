## Description
Fixes: https://github.com/zulip/zulip/issues/24109
The issue states that when trying to collapse a muted user's message, it does not work as intended. In the issue, it states that when a user is muted, the collapsed message should be the same if the message is hidden. If the message is collapsed and then revealed, the message should just be in a collapsed state. This will help the user know who the muted user is, while having the message still hidden from them. 

To fix this, I worked with An Pham @apham1142 to edit the condense.ts class and the message_list_view.ts class. We specifically changed the process_row() function in condense.ts to make sure that it checks if the message does not have a .muted-message-sender class to it before it applies the collapse function. We also edited the collapse_and_condense () function so that if it is not hidden, then the collapsed class is attached to the message.

We then changed the message_list_view.ts class to make sure that the messages are rerendered in _rerender_message() correctly. It now triggers the condense_and_collapse() function immediately after a new message row replaces the old one in the DOM, ensuring that any post-render UI states, like hovering or collapsing, are reapplied.

**How changes were tested:**
- Tested muting a user and then collapsing a message.
*No change in the message, as the intended solution.*
We did notice that there could be an issue where the user wants to hide the message after the message is expanded. Maybe a fix could be adding the option in the message actions, or we could simply have the hide button appear next to the show more button.

- Tested collapsing a message and then muting a user.
*Has the "show more" button, but when clicked, the message is still hidden.*

- Tested normally collapsing a message and expanding a message with no muted user
*Collapsing and expanding works as intended*
