## Description
This PR implements the three convenience features requested in #20316,
split into three commits:

1. **Fix broken drag-and-drop upload** the existing single-file
   drag-and-drop silently failed for two reasons: the drop handler never
   called `preventDefault()` on `dragover` (so browsers opened the
   dropped file instead), and setting `.files` on the input element
   programmatically doesn't fire native `input`/`change` events on its
   own, which the auto-fill and submit-button logic both depend on.
   Fixed by triggering both events after a drop, and widened the drop
   target from the small upload button to the whole upload area via a
   `$drop_zone` parameter, refactored so avatar/realm icon/realm logo
   uploads (which remain single-file only) are unaffected.
2. **Auto-fill emoji name** from the selected file's name (extension
   stripped), only when the name field is currently empty, so manual
   edits are never overwritten.
3. **Multi-file upload**, via file picker and drag-and-drop. Since emoji
   names are user-meaningful and must be unique, each file's name is
   derived from its filename, and files are submitted as separate
   requests. If some fail (e.g. duplicate name), successful ones are
   kept and the user is told which ones failed.

### Testing

Manually tested single-file upload via picker (with/without existing
name), single- and multi-file upload via drag-and-drop, and
partial-failure handling (duplicate names). Confirmed the existing
default-emoji override confirmation flow still works for single-file
uploads. Added automated tests covering the widget wiring, the
filename-derivation logic used by multi-file upload, and the auto-fill
behavior itself.
