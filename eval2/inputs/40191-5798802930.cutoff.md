## Description
### Description

In accordance with Zulip's naming convention guidelines and #23380, this PR replaces occurrences of the deprecated `URI` abbreviation in favor of `URL` in the avatar and logo settings.

Following Zulip's commit discipline guidelines, the changes are split into atomic, independent commits:

1. **`settings: Rename DEFAULT_AVATAR_URI to DEFAULT_AVATAR_URL.`**
   - Renames `DEFAULT_AVATAR_URI` to `DEFAULT_AVATAR_URL` in `zproject/default_settings.py` and `zproject/prod_settings_template.py`.
   - Adds backward-compatibility fallback in `zproject/computed_settings.py` (`DEFAULT_AVATAR_URL = DEFAULT_AVATAR_URI` if unset) and explicitly exports it.
   - Updates `zerver/lib/avatar.py` and `zerver/lib/realm_icon.py` to use `DEFAULT_AVATAR_URL` with fallback to `DEFAULT_AVATAR_URI`.
   - Updates tests in `zerver/tests/test_upload.py` and adds settings-layer fallback test in `zerver/tests/test_server_settings.py`.

2. **`settings: Rename DEFAULT_LOGO_URI to DEFAULT_LOGO_URL.`**
   - Renames `DEFAULT_LOGO_URI` to `DEFAULT_LOGO_URL` in `zproject/default_settings.py`.
   - Adds backward-compatibility fallback in `zproject/computed_settings.py` (`DEFAULT_LOGO_URL = DEFAULT_LOGO_URI` if unset) and explicitly exports it.
   - Updates `zerver/lib/realm_logo.py` to use `DEFAULT_LOGO_URL` with fallback to `DEFAULT_LOGO_URI`.
   - Updates tests in `zerver/tests/test_upload.py` and adds settings-layer fallback test in `zerver/tests/test_server_settings.py`.


Fixes part of #23380.

The Home Assistant documentation fix has been moved to a separate PR, as requested in review.

### #23380 (issue, open): Stop using the deprecated "uri" terminology in favor of "url"
Opened by timabbott (MEMBER). Labels: help wanted, area: refactoring. Assignees: none.
Description: We should stop using the deprecated "uri" abbreviation in favor of "url". There's some complicated history for the terminology in general touched on in https://github.com/zulip/zulip-mobile/blob/main/docs/style.md#url-not-uri. 

This is a very rough way to investigate how we we use these in the web app; not a huge number of references in the server codebase (though there's a lot more in templates and the like).

```
(zulip-py3-venv) tabbott@coset:~/zulip$ git grep _uri zerver/ | wc
    105     410    9316
(zulip-py3-venv) tabbott@coset:~/zulip$ git grep [.]uri zerver/ | wc
     89     381    8161
```

The vast majority of these will be things we can just change, though we should do this thoughtfully in a reviewable way, with one commit per thing. For example, renaming `encode_zuliprc_as_uri` should be a single commit that changes all references to that variable.

The one thing that will hard will be this line: `zerver/lib/events.py:        state["realm_uri"] = realm.uri`, which is an API change; we should save that for last (as it'll likely require adding a new `realm_url`, leaving the old name available for mobile clients and other API tools that we don't want to break compatibility for), after we've renamed all the smaller uses that don't require this API change.
