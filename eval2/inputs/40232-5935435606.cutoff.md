## Description
Sorting the custom emoji table by Author now places the current user's own emoji at the top, as requested in the issue. Everyone else's emoji keep the existing alphabetical-by-author-name ordering, and emoji by the same author still fall through to the table's name sort.

Fixes: #8170

**How changes were tested:**

Added a node test that captures the `author_full_name` comparator from the options passed to `ListWidget.create`, then asserts that the current user's emoji sorts first even when the other author's name sorts earlier alphabetically. The test fails without this change.

Manually tested in the development environment, logged in as King Hamlet — whose name sorts last among the authors used — with custom emoji uploaded by Iago, Cordelia and King Hamlet.

One decision worth flagging: `list_widget` negates the comparator's entire return value in reverse mode (`web/src/list_widget.ts` line 353), so clicking the Author header a second time moves the current user's emoji to the bottom. I read that as correct — sorting by Author groups the table, and reversing a grouped sort should reverse the groups. It matches how rows with an unknown author already behave, and @timabbott's suggestion in this issue was to "sort the current user to one end of the alphabetical list". Happy to pin the current user to the top in both directions instead, but that would need a change in `list_widget` rather than in this file.

**Screenshots and screen captures:**
