## Description
Fixes a bug where resending a message that failed to send left its draft behind in the drafts overlay. Split out of #38356, where it was found [during review](https://github.com/zulip/zulip/pull/38356#discussion_r3786243126).

`reify_message_id` converts a locally echoed message into a server message in place, which deletes its `draft_id`. `send_message_success` read `sent_message.draft_id` after that call, and a resend passes the stored `LocalMessage` itself rather than a copy of the request, so the call became `deleteDrafts([undefined])`: the message was sent, but its draft stayed.

This is reachable on `main` today, without any of the changes in #38356: `on_failed_action` wires the feed's retry button straight to this path, and a failed send never clears the message from `waiting_for_id` (only `reify_message_id` itself and `abort_message` do), so on retry `reify_message_id` does not early-return and does drop `draft_id`.

The fix reads `draft_id` off the message before reifying.

### #38356 (PR, open): drafts: Add Outbox tab to drafts overlay
Opened by Aadyot1 (COLLABORATOR). Labels: size: XL, area: compose (drafts/network/echo), new feature, maintainer review. Assignees: evykassirer.
Description: Fixes #32999.

Adds an Outbox tab to the drafts overlay to list messages that failed to send.

Previously, failed messages were converted into regular drafts, making them easily lost. Now, they are routed directly to the Outbox tab where they can be retried or canceled, either individually or in bulk.

Canceling an outbox message successfully removes the corresponding local echo from the message feed.

The tab switcher only appears when there are outbox messages. Once the last outbox message is canceled or sent, the overlay automatically returns to the normal drafts view.
