## Description
Previously, `PATCH /json/users/me/profile_data` (updating a user's custom profile
fields) ran a linear number of DB queries in the number of fields
being updated,

- `validate_user_custom_profile_data` ran one `CustomProfileField.objects.get()` query per field.
- `do_update_user_custom_profile_data_if_changed` ran one `get_or_create()` query per field, plus a separate lazy
  `field_value.field` fetch per field (no `select_related`) used by `is_renderable()` and `get_custom_profile_field_display_value()`.

There's no cap on how many custom profile fields a realm can define,
so this scales with org size. Measured end-to-end (test realm, 9
fields, updating all of them in one request): **44 queries**.

Fixes: N/A, Raised as a performance improvement in https://chat.zulip.org/#narrow/channel/3-backend/topic/n.2B1.20queries.20in.20custom.20profile.20field.20update.20endpoint/with/2505937


**What this PR does:**

Two independent batching changes, one per commit:

1. `validate_user_custom_profile_data`: replace the per-field
   `.get()` with a single `filter(id__in=...)` query plus an
   in-memory dict lookup.
2. `do_update_user_custom_profile_data_if_changed`: replace the
   per-field `get_or_create()` with a single bulk fetch of existing
   values, pre-populate the FK cache for `field_value.field` (so
   `is_renderable()`/`get_custom_profile_field_display_value()` don't
   trigger extra queries), and batch writes via `bulk_create()`/
   `bulk_update()` instead of per-field `.save()`.


Behavior is unchanged: Verified against the original implementation with a side-by-side comparison (identical changes list, identical notify call arguments, identical resulting field values) before porting the
logic into these files.


**Result:**

44 queries **drops to** 14 queries for the same 9-field update, verified via a new
`assert_database_query_count` regression test
(`test_update_profile_data_query_count`) that pins this as the new
baseline, per Zulip's existing convention for this endpoint category.


**How changes were tested:**


- `./tools/test-backend zerver.tests.test_custom_profile_data`: clean
- Full `./tools/test-backend` suite: 2 pre-existing failures in `test_user_groups.py`, confirmed unrelated by reproducing them on a clean `main` before this branch's changes.
