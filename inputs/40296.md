## Description
Fixes: `PATCH /settings` returning a 500 error for some invalid timezone names, instead of "Not a recognized time zone". CZO discussion: [#issues > 500 error for timezone "America" in settings API](https://chat.zulip.org/#narrow/channel/9-issues/topic/500.20error.20for.20timezone.20.22America.22.20in.20settings.20API/near/2532729)

`zoneinfo.ZoneInfo` looks up keys as files under the tzdata directory, so some invalid keys raise `OSError`, which `check_timezone` and `to_timezone_or_empty` didn't catch:

- Directory names like `America`, `Europe` or `Etc` raise `IsADirectoryError`.
- Keys of 256 or more characters raise `OSError: [Errno 36] File name too long`.

To reproduce on `main`: `curl -u EMAIL:API_KEY -X PATCH http://localhost:9991/api/v1/settings -d timezone=America`

`to_timezone_or_empty` is used by the registration and demo organization creation views, so it gets the same fix.

**Alternative considered:** checking the key against `zoneinfo.available_timezones()` instead. I didn't do that because it walks the tzdata directory on every call, and catching `OSError` is consistent with how the existing code handles invalid keys. Happy to switch if reviewers prefer that.

**How changes were tested:**

- [x] Added tests for `check_timezone` and `to_timezone_or_empty` covering a directory name and a 256-character name. Both fail on `main` with `IsADirectoryError` and pass with this change.
