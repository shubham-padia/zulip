## Description
This PR adds **Confluence Server/Data Center** (`confluence`). 

The complementary PR #39424 integrates Confluence Cloud deployment.

Confluence Server's built-in webhooks send only content IDs in their payloads (e.g.:

```
{
  "timestamp": 1778071365412,
  "event": "blog_created",
  "userKey": "def456",
  "page": {
    "id": 234567
  }
}

```
),
so the handler makes REST API callbacks using a personal access token to fetch page, blog post, and comment details. The base_url is passed as a webhook URL parameter. The personal access token is stored as bot configuration (confluence_token) via WebhookConfigOption, so it is not included in the URL.      
Note: no frontend UI exists yet for setting WebhookConfigOption values when creating an incoming-webhook bot. Until that UI is added, the confluence_token must be set through the API (POST /json/bots with config_data).                                                                                                                                    
                                                                                                                                                                                                                
This integration handles page, blog post, and comment events (created, updated, restored, trashed, moved). 

Fixes part of https://github.com/zulip/zulip/issues/5142.

**Local Confluence Server setup via Docker:** To reproduce the end-to-end testing locally, you can spin up a Confluence Server instance using the following `docker-compose.yml`:
```
services:
  postgres:
    image: postgres:15
    container_name: confluence-postgres
    environment:
      POSTGRES_DB: confluence
      POSTGRES_USER: confluence
      POSTGRES_PASSWORD: confluence
    volumes:
      - postgres-data:/var/lib/postgresql/data

  confluence:
    image: atlassian/confluence
    container_name: confluence
    depends_on:
      - postgres
    ports:
      - "8090:8090"
      - "8091:8091"
    volumes:
      - confluence-data:/var/atlassian/application-data/confluence

volumes:
  postgres-data:
  confluence-data:
```     
Once Confluence is running, complete the setup wizard and activate a license. For testing without a paid license, use the **timebomb licenses** provided by Atlassian for server app testing: https://developer.atlassian.com/platform/marketplace/timebomb-licenses-for-testing-server-apps/
