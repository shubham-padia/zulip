## Description
Migrate the `stream_does_not_exist` compose banner from the legacy `.main-view-banner` markup to the modern banner component.

This is the first incremental migration of the remaining compose banners in #39794. The existing `error` and `stream_does_not_exist` classes are preserved so the current validation and banner-clearing behavior continues to work, while the existing message content is reused.

**What changed**
- Replaced the legacy `stream_does_not_exist_error.hbs` banner template with the modern `banner.hbs` component.
- Added a dedicated `stream_does_not_exist_error_message.hbs` template for the banner's message content.
- Updated `show_stream_does_not_exist_error()` to render the modern banner with the `danger` intent.
- Preserved the existing `error` and `stream_does_not_exist` classes so the existing validation and banner-clearing behavior continues to work.
- Kept the existing `append_compose_banner_to_banner_list()` flow so this banner continues to behave as a compose banner.
- The existing error message and user-facing behavior are otherwise unchanged.

**Why**
The `stream_does_not_exist` compose banner was still using the legacy `.main-view-banner` markup. This migration brings it in line with the modern banner component as part of the incremental migration described in #39794, while preserving the existing functionality and behavior.

Fixes #39794

### #39794 (issue, open): Migrate compose and message-edit banners to the modern banner component
Opened by Yogesh-Shivaji365 (COLLABORATOR). Labels: area: compose (banners & validation), area: message-editing, area: compose, good first issue, help wanted, in progress. Assignees: sonua11y.
Description: The compose box and message-edit banners still use the legacy `.main-view-banner` markup, instead of the modern banner component
(`web/src/banners.ts`, viewable in the development environment at http://localhost:9991/devtools/banners/).

Because the legacy close button is an `<a role="button" tabindex="0">`, it takes focus on mouse clicks and shows a focus outline. That was worked around in #39759 with a `:focus:not(:focus-visible)` rule and a TODO pointing here; migrating would let us drop the workaround.

Note that the two components use different layout systems (flexbox vs. CSS grid, different padding, line height, and close button size), so this will change how the banners look worth confirming the intended [design](https://chat.zulip.org/#narrow/channel/101-design) before implementing.
