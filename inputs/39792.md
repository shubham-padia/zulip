## Design notes

- **One call group per channel and unique room per every call.**  Galène's group URL layout:

    - Normal topics: {GALENE_URL}/group/{channel}/{topic}-{uuid}.
    - Empty channel: {GALENE_URL}/group/general_calls/{topic}-{uuid}.
    - Empty topic: {GALENE_URL}/group/{channel}/{uuid}.
    - DMs: {GALENE_URL}/group/dm/{comma_separated_participant_ids}--{uuid}.
    
The benefits of having unique call IDs are starting two simultaneous calls in the same topic (e.g., two separate breakout discussions), avoiding realm collisions, and preventing uninvited users from guessing room names.

- Rooms are ephemeral; we use Galène's auto-subgroups so nothing needs to be provisioned or cleaned up server-side. However the parent group per Zulip channel is written to Galène's disk and persists.

- **Permissions map from Zulip roles to Galène roles.**

  - Zulip moderators (incl. admins and owners) → Galène **operators**.
  - Zulip members and guests → Galène **presenters** (can turn on their camera).
  - In a DM call, **everyone is an operator**, since the participants are the only people who can be there.

```
mkdir data
openssl req -newkey rsa:2048 -nodes \

  -out data/cert.pem \
  -subj "/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,DNS:host.docker.internal,IP:127.0.0.1,IP:172.17.0.1"
</details>
```
3. Bootstrap credentials 
```
su -l galene
galenectl -admin-username admin initial-setup
mkdir data
mv config data/
```
Edit dev-secrets.conf to add the credentials.

4. Run galene

```
./galene -insecure -http 0.0.0.0:8080
```

### #38516 (issue, open): Galène support as video call provider
Opened by kousu (NONE). Labels: area: integrations (video calls). Assignees: none.
Description: [Galène](https://galene.org/) is a new beautifully low-resource WebRTC conference call server. It supports moderated and unmoderated rooms, invite links, and account passwords, it works well on mobile and scales to ~50 users easily (the authors claim it's been used for up to 200 user lectures).


<img width="626" height="455" alt="Image" src="https://github.com/user-attachments/assets/bee7ef98-8983-4f7d-ad48-0e8d89504c89" />

<img width="622" height="697" alt="Image" src="https://github.com/user-attachments/assets/15d85e81-5fa4-4e15-8bd5-35b2d756023f" />

I wonder if it could become a Zulip [Call Provider](https://zulip.com/help/configure-call-provider). I see that for BBB [there is a framework to share a secret](https://zulip.com/integrations/big-blue-button) -- Galène should be similar.

It has a tree of call rooms (which it calls "groups"); for Zulip's purposes, either rooms could be created at the top level (e.g. /groups/xuy28fyYYf3), or a top-level group (e.g. /groups/calls) could be specified by the admin and Zulip could make sub-groups under it (e.g. /groups/calls/xuy28fyYYf3). Invites can have usernames baked in to them which means Zulip should be able to map the names people get from its own database.

It would be great to have this integration in Zulip. Galène is 50 times simpler to install than either Jitsi or BigBlueButton or NextCloud, and it works equally well as any of them. It took me an hour to get it up and fully working, even allowing time to get it working behind a reverse proxy.
