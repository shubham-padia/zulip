## Description
Optimize the channel settings UI to avoid unnecessary DOM reordering when filtering channels.

Previously, `redraw_left_panel` detached and re-appended all channel rows on every redraw, even when the desired channel order was unchanged. With hundreds of channels, this caused noticeable input lag while filtering, especially when holding Backspace to clear the search query.

This change compares the current channel order with the desired order and only detaches and re-appends rows when the order actually needs to change. Visibility updates still happen normally without unnecessary DOM reordering.

A regression test verifies that rows are not detached when they are already in the requested order.

Fixes: #39755

### #39755 (issue, open): Manage channels overlay freezes browser for ~80 seconds with ~330 channels
Opened by ryanmanalaysay-tvt (NONE). Labels: bug, area: channel settings. Assignees: none.
Description: ## Summary

On a self-hosted Zulip Server 12.1 installation, opening the **Manage channels** overlay on views that display the full channel list causes the browser tab to become unresponsive for tens of seconds.

Affected views include:

- `#channels/new`
- The **All** tab in Manage channels
- Other views that render or rebuild the full channel list

Chrome displays the **Page Unresponsive** dialog. The page eventually recovers after approximately 80 seconds, but the interface is effectively unusable during that time.

A Chrome CPU profile indicates that this is not a server, network, data-fetch, or browser-extension issue. Approximately 90% of the freeze is spent in two DOM operations triggered by Zulip's webapp code through bundled jQuery:

- `removeChild`
- `querySelectorAll`

This reproduces with only approximately **331 channels**, significantly below the 5,000-stream scenario discussed in older issue #10902. This may be a regression or a related performance issue affecting smaller organizations.

## Environment

- **Zulip Server version:** 12.1
- **Upgrade path:** In-place upgrade from Zulip 9.4
- **Install type:** Standard non-Docker installation
- **Operating system:** Debian 12 Bookworm
- **Database:** External PostgreSQL 16.8 on AWS RDS
- **Browser:** Google Chrome on macOS
- **Organization size:** Approximately 331 channels
- **Channel visibility:** Large majority are private/invite-only
- **Test user:** Administrator subscribed to only a handful of channels

Web bundles visible in the performance profile:

```text
app.560f7c2cbda07d532282.js
420.288148b70ab4f3988e8c.js
```

The second bundle contains the bundled jQuery code involved in the profile.

## Steps to reproduce

1. Use an organization containing a few hundred channels.
   - Our organization has approximately 331 channels.
   - Most channels are private/invite-only.
2. Sign in as an administrator subscribed to only a small number of those channels.
3. Open **Manage channels**:
   - Gear menu → **Channel settings**
   - Navigate directly to `#channels/new`
   - Open the **All** tab
4. Observe that the browser's main thread becomes blocked for tens of seconds.
5. Chrome may display its **Page Unresponsive** dialog.

The **Subscribed** tab, which displays only the few channels the current user belongs to, renders normally. The freeze occurs when Zulip renders or rebuilds the complete channel list.
