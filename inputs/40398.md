## Description
When two concurrent realm creation requests attempt to register the same subdomain, both can pass the initial availability validation check before either realm is created in the database. When the second request calls `do_create_realm`, PostgreSQL raises an `IntegrityError` due to unique constraint violations (`zerver_realm_string_id_key` or historical `zerver_realm_subdomain_key`).

Previously, this resulted in an unhandled 500 Internal Server Error crash for the second user.

This PR fixes the issue by:
1. Catching `IntegrityError` around `do_create_realm` in `zerver/views/registration.py`.
2. Verifying the constraint violation is specifically for the subdomain (`is_string_id_unique_violation`), allowing unrelated database errors to propagate rather than being swallowed.
3. Extracting a reusable `render_registration_form` helper to re-render the registration form with a field-level error message and HTTP 400 Bad Request status.
4. Preserving submitted values (organization name, etc.) and the confirmation key so the user can immediately choose another subdomain without consuming or breaking the confirmation link.

Fixes: #21160

### #21160 (issue, open): Race condition in realm creation
Opened by alexmv (MEMBER). Labels: area: production, help wanted, in progress. Assignees: Tanaya-2007.
Description: It's possible for two realm creations with the same name to race, which triggers a 500 and raises an exception:
```
duplicate key value violates unique constraint "zerver_realm_subdomain_key"
DETAIL:  Key (string_id)=(duplicate-realm-name) already exists.
```

This is raised by `realm.save()` in `do_create_realm`, which is (correctly) inside a `transaction.atomic()` so we don't get inconsistent state in the database.  The only problem is the potential user experience; `accounts_register` in `zerver/views/registration.py` should catch the IntegrityError that is so raised, and return a 400, not a 500.
