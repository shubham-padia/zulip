## Linked issues and PRs
### #40185 (issue, open): Negated 'with' narrows are silently treated as positive
Opened by Indra55 (NONE). Labels: bug, area: api, in progress. Assignees: Indra55.
Description: `with` is a navigation operator (permalink to a topic via message ID), not a filter. Negating it doesn't make sense, and the web client already rejects `-with:<message_id>`. The server doesn't.

### Steps to reproduce

1. Get a message ID you can access, `MESSAGE_ID`.
2. `GET /api/v1/messages` with this narrow:

```json
   [{"operator": "with", "operand": MESSAGE_ID, "negated": true}]
```

3. Compare to the same request with `"negated": false`.

### Actual behavior

Same result either way. `update_narrow_terms_containing_with_operator` in `zerver/lib/narrow.py` pulls out the `with` term and resolves it without ever checking `.negated`.

### Expected behavior

Negated `with` should raise `BadNarrowOperatorError`, same as the web client does for `-with:`.
