## Description
Some Markdown that is non-empty as text still renders to nothing visible: an empty math span (`$$ $$`), or a block (math, code, quote, spoiler) with a whitespace-only body. Sending these created a blank, empty-looking message in the feed.

This blocks sending/saving such messages, treating them like an empty message

Fixes: [#issues > send message with empty Math block.](https://chat.zulip.org/#narrow/channel/9-issues/topic/send.20message.20with.20empty.20Math.20block.2E/with/2486579)

## The blocking problem: the "renders blank" enumeration is wrong in both directions

I rendered each case the commits assert about. Results:

| Input | Actual rendered output | Guard says |
|---|---|---|
| `` ```\n``` `` | `''` — **totally blank** | not blank ✗ |
| `` ```spoiler Header\n``` `` | `''` — **totally blank** | not blank ✗ |
| `` ```math `` (unclosed) | empty `katex-display` — blank | not blank ✗ |
| `` ```math foo\n``` `` | `''` — **totally blank** | not blank ✗ |
| `    $$ $$` (4-space indent) | `<div class="codehilite"><pre><code>$$ $$</code></pre></div>` — **visible** | blank ✗ |
| `    ~~ ~~`, `\t$$ $$` | visible code block | blank ✗ |
| ` ```math\n ``` ` (1–3 space indent) | `<p><code>math…</code></p>` — **visible** | blank ✗ |
| `~~\u00A0~~` | `<p><del>\u00A0</del></p>` — **visible struck dash** | blank ✗ |

### False positives — valid messages become unsendable

[compose_validate.ts:1060-1079](web/src/compose_validate.ts#L1060-L1079)

The guard strips the inner text and `.trim()` erases the remaining indent → blocked.
