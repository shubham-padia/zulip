## Description
Allow everyone to manually reorder todo tasks by dragging and dropping them in the widget, addressing the third bullet under "Sorting" in #20213.

Fixes part of zulip#20213



Drag-and-drop uses SortableJS, which the codebase already uses elsewhere rather than introducing a new pattern.
Reordering broadcasts a `{key, after_key}` rather than the whole task order, so a task added by someone else mid-drag can't be silently dropped from the list.

- Manually tested dragging tasks up/down as the task list author
- Ran the full backend and frontend test suites locally

## Linked issues and PRs
### #20213 (issue, open): Improve /todo widget usability
Opened by alya (MEMBER). Labels: help wanted, feedback wanted, area: message feed display, area: widgets, area: compose (widgets), priority: high, umbrella list. Assignees: none.
Description: The `/todo` command creates a to-do list widget. This widget has basic functionality, but lacks some features that would make it more useful. This issue describes a bunch of these features. They do not need to be addressed all at once -- we can integrate work that adds any of these independently.

## Sorting
At present, tasks are sorted _not done_ > _done_, and alphabetically within those categories. Improving this is the most important priority for this feature.

- [x] Do not resort tasks when checked/unchecked. This makes the ordering confusing, and we'd be better off just leaving them as-is.
- [x] Order tasks by the time they are created (newest on the bottom) rather than alphabetically.
- [ ] Make it possible to manually reorder tasks, ideally by dragging and dropping them in the message view.

## Creating and editing
- [x] Allow naming a to-do list (currently always titled "Task list". We can keep the default title, but like a `/poll`, it should be possible to name the list in two ways:
1) By including the title on the same line as `/todo` when creating the list (e.g. `/todo My task list`)
2) The author should be able to edit the list by clicking on a pencil button next to the title (again, cf. `/poll`).
- [x] Like a `/poll`, it should be possible to add tasks at creation time by putting them (one per line) below the `/todo` command. We will need a separator for the task name vs. description; a `:` is probably the most intuitive. For the initial version, it would be OK if it was impossible to use a `:` in the name of the task. 
- [ ] The user who added a task (or perhaps everyone who can add tasks) should be able to edit its name and description. 
- [ ] The user who added a task (or perhaps everyone who can add tasks) should be able to delete it.

### Assigning tasks
- [ ] Barring fancier assignment functionality being implemented, we should at least have @-mentions work in task titles and descriptions. Requested in #29707.
