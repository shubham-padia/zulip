## Description
Fixes #39831.

### Description
Previously, `add_embed()` skipped rendering any preview when `extracted_data.image` was `None`, even when useful title and description metadata was successfully extracted. This caused pages without Open Graph images (technical docs, static sites, older websites) to appear only as bare links.

Now, when a title or description is available but no image is found, Zulip renders a compact text-only preview card. The existing image-based preview remains unchanged when an image is available. If no useful metadata is available at all, the URL remains a bare link.

### #39831 (issue, open): Support website previews without a preview image
Opened by hdmr14 (NONE). Labels: in progress, area: message feed (embeds). Assignees: paul-raja-dev.
Description: ## Proposal

Zulip should render a compact text-only website preview when a page title or description is available but no preview image can be found.

Currently, a generic website preview is not rendered when `extracted_data.image` is `None`, even if the parser successfully extracts a useful title and description.

## Example

Posting the following URL produces only a bare link:

https://box2d.org/posts/2026/06/announcing-box3d/

The page is fetched successfully with HTTP 200 and `Content-Type: text/html; charset=utf-8`.

Running the URL preview parsers directly on Zulip 12.1 produces:

```text
OpenGraphParser UrlEmbedData(
    type=None,
    html=None,
    title=None,
    description=None,
    image=None
)

GenericParser UrlEmbedData(
    type=None,
    html=None,
    title="Announcing Box3D :: Box2D",
    description="I’m happy to announce the release of Box3D, an open source 3D physics engine...",
    image=None
)
```

Thus, Zulip successfully extracts meaningful text metadata, but the preview is not displayed because no image was found.

The relevant behavior in `InlineInterestingLinkProcessor.add_embed()` is:

```python
if extracted_data.image is None:
    # Don't add an embed if an image is not found
    return
```

## Expected behavior

When a title or description is available, Zulip should render a compact text-only preview even when no image is available.

For example, the fallback preview could contain:

* The page title, linked to the URL
* A shortened description
* Optionally, the hostname or favicon
* No empty image placeholder

The existing image-based preview could remain unchanged when an image is available.

A possible decision flow would be:

1. If an image and text metadata are available, render the existing preview card.
2. If no image is available but a title or description is available, render a text-only card.
3. If no meaningful metadata is available, leave the URL as a bare link.

## Motivation

Many useful pages do not provide an Open Graph image, including technical articles, documentation, internal tools, small static websites, and older websites.

Zulip may already successfully download these pages and extract their title and description. Discarding all of that information solely because an image is unavailable makes link previews appear inconsistent.

A text-only fallback would make website previews more useful and reliable without requiring every website to publish social-media image metadata.
