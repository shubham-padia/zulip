## Description
Fixes: #40163

When a developer has conflicting versions of Node.js (such as via NVM) or `uv` earlier in their `PATH`, `scripts/lib/install-node` and `scripts/lib/install-uv` fail during the post-installation `check_version` call.

Previously, `check_version` failing caused the script to exit abruptly with exit code 1 with no explanation. Following the discussion in #40164, this change prints a clear diagnostic error on failure reporting the expected version, the version found, and steps to resolve the `PATH` conflict.

### #40163 (issue, closed): `tools/provision` fails  if user already has NVM or local `uv` installed
Opened by Ali-Razahaider (CONTRIBUTOR). Labels: bug, question. Assignees: none.
Description: ### Description


This issue occurs when setting up Zulip using the [Advanced setup (non-Vagrant)](https://zulip.readthedocs.io/en/latest/development/setup-advanced.html) method on a native Linux machine (Linux Fedora Workstation 44 ).

**Expected behavior:**
Running `./tools/provision` should install Zulip's Node.js (`v24.19.0`) and `uv` (`0.12.5`) tools and complete successfully.

**Actual behavior:**
Setup fails during `install-node` or `install-uv`. If you already have NVM or a local `uv` installed on your computer, your terminal finds your old version first instead of Zulip's newly installed version.

When the installer checks if the tool was installed (`check_version`), it tests your old personal version instead of Zulip's version sitting in `/srv/zulip-node` or `/usr/local/bin`. Because the version numbers do not match, provisioning stops with exit code 1.

This does not happen in the recommended [Vagrant setup](https://zulip.readthedocs.io/en/latest/development/setup-recommended.html) because the Vagrant/Docker container has a clean environment without user-level tool installations.

---

### Steps to reproduce

1. Have NVM or a local `uv` installed on your system (e.g. `nvm install 24.14.1`).
2. Follow the [Advanced setup](https://zulip.readthedocs.io/en/latest/development/setup-advanced.html) instructions:
   ```bash
   git clone https://github.com/zulip/zulip.git && cd zulip
   ```
3. Run `./tools/provision` on your Linux machine.
4. Provisioning fails in `install-node` or `install-uv` with a version error.

---

### Why it happens

In `scripts/lib/install-node` and `scripts/lib/install-uv`, the `check_version()` function checks version using plain commands:

* `node --version`
* `uv --version`

Since the personal tool folder of the user (`~/.nvm/` or `~/.local/bin/`) comes first in the PATH environment variable, Linux runs that personal version instead of Zulip's freshly installed version.

Zulip's [documentation on Node.js](https://zulip.readthedocs.io/en/latest/subsystems/dependencies.html#node-js-and-pnpm) states that it manages its own Node and no longer uses NVM, but `scripts/lib/install-node` only removes the old system `/usr/local/nvm` — a personal `~/.nvm` in the user's home directory is not handled.

### #40164 (PR, closed): Fix: Failing version checks in install-node and install-uv.
Opened by Ali-Razahaider (CONTRIBUTOR). Labels: size: XS. Assignees: none.
Description: ## Closes #40163  
### Summary of Changes

When running `./tools/provision` on native Linux setups, `scripts/lib/install-node` and `scripts/lib/install-uv` invoke a `check_version()` function that verifies tool installation by calling `node --version` and `uv --version`.

Because `tools/lib/provision.py` runs these scripts via `sudo --preserve-env=PATH`, the user's environment `$PATH` ordering is preserved. If a developer has an existing installation of Node.js (such as via NVM) or `uv` in `~/.local/bin` that appears earlier in `$PATH` than `/srv/zulip-node/bin` or `/usr/local/bin`, bash executes the user's pre-existing version rather than the freshly installed system version. This causes the version assertion in `check_version()` to fail and stops provisioning with exit code 1.

This PR fixes the issue by explicitly invoking the absolute paths to the installed binaries (`/srv/zulip-node/bin/node` and `/usr/local/bin/uv`) inside `check_version()`. This ensures the installer checks the freshly installed tool versions regardless of the developer's local environment.

Fixes: Version verification failure in `./tools/provision` on systems with user-level NVM or uv in `PATH`.

---
