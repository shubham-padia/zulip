## Description
On macOS, the native browser shortcut for switching to the next tab is `Cmd + Shift + ]`. Previously, Zulip's `compose_ui` keydown handler intercepted this combination and unexpectedly indented the list, because the event listener condition only checked for `Cmd` and `]`.

This PR adds an explicit `!event.shiftKey` check, mirroring how italic and link shortcuts are natively handled, to ensure list indentation safely ignores native OS tab-switching shortcuts.

Fixes: #40112

**How changes were tested:**

I verified locally that pressing `Cmd + ]` still correctly indents list items in the compose box. I also verified that pressing `Cmd + Shift + ]` no longer triggers the list indentation code path, allowing the browser to natively switch tabs without unexpectedly altering the compose box text.

I've investigated this bug and traced the exact root cause.

The issue stems from web/src/compose_ui.ts inside the handle_keydown function (around line 688). Currently, the shortcut for indenting lists (Cmd + ]) fires based on this condition: isCmdOrCtrl && (key === "]" || key === "[")

Because Cmd + Shift + ] is a native macOS browser shortcut for switching to the next tab, pressing it evaluates to key === "]" while both event.metaKey and event.shiftKey are true. Zulip intercepts the keystroke and unexpectedly indents the text simultaneously as the browser shifts the tab.

My Plan for the PR: I will patch this by explicitly adding a !event.shiftKey check to the list indent condition (similar to how the italic and link formatting shortcuts handle it above it).
