## Description
Quoting a multi-message selection fetched each message's full `raw_content` and quoted each message in full, ignoring how much of the first and last messages was actually selected.

This quotes just the selected portion of those bookend messages instead, mirroring what copy already does; messages fully inside the selection keep their `raw_content`, which round-trips more faithfully. The bookend range is expanded for mentions/timestamps/KaTeX.

Fixes: #39631.

That's the catch: the multi-message quote pipeline doesn't use the DOM selection at all; it fetches each message's full `raw_content`. So the issue's ask "expand the selection for mentions/katex/timestamps," can't take effect yet, because no partial selection is being quoted to expand.

So the PR does two things:

1. Makes multi-message quoting the selection for the first/last (bookend) messages, quoting only the selected portion (like copy already does in `construct_copy_div`); middle messages keep full `raw_content`.

2. Applies the mention/katex/timestamp range-expansion on those bookend ranges, the part the issue actually describes.

Step 1 is just the enabler for step 2. But it does change multi-message quote behavior, and #37878 deliberately used full `raw_content`, so if that's not the intended scope.
