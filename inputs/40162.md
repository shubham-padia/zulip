## Description
covering #40043 
Currently, adding a new Code Playground in Organization Settings uses an inline form permanently visible above the configured playgrounds list. This design pattern differs from the standard UI approach used across Zulip admin settings (e.g., Linkifiers, Custom Emoji, and Custom Profile Fields), which use a clean action button that launches a dedicated modal dialog.

This PR moves the Code Playground creation form into a dedicated modal dialog launched from an "Add code playground" action button.

Key changes:
- **UI Templates**: Created `web/templates/settings/admin_playground_add_form.hbs` for the modal dialog content. Updated `web/templates/settings/playground_settings_admin.hbs` to replace the inline highlight box with an "Add code playground" action button and notification banner.
- **Frontend Logic**: Updated `web/src/settings_playgrounds.ts` to wire up the action button with `dialog_widget.launch`, initialize pygments language typeahead in the modal, and submit via `dialog_widget.submit_api_request`. Preserved the 3000ms auto-fadeout on the success banner.
- **Styling**: Removed obsolete inline playground form rules from `web/styles/settings.css`.
- **Linter**: Updated `tools/linter_lib/custom_check.py` to register the new modal template for untranslatable placeholder checks.
- **E2E Tests**: Updated Puppeteer end-to-end test in `web/e2e-tests/realm-playground.test.ts` to test opening the modal, selecting language via typeahead, handling validation errors, submitting valid playgrounds, and modal dismissal.

Fixes #40043.

Description: ## Problem Statement

Currently, adding a new Code Playground in Organization Settings uses an inline form permanently visible above the configured playgrounds list.

**Current Playground UI:**

<img width="3072" height="1664" alt="Image" src="https://github.com/user-attachments/assets/afec7703-b7be-4842-8040-bd4bedc010b7" />

This design pattern differs from the standard UI approach used throughout the rest of the Zulip admin settings. For example, similar administrative configurations (like Linkifiers, Custom Emoji, or Custom Profile Fields) all use a clean "Add [Entity]" button that launches a dedicated modal.

**Standard Target UI (e.g., Linkifiers):** 

<img width="3072" height="1664" alt="Image" src="https://github.com/user-attachments/assets/a9816076-eb22-4230-a4dd-ce20488cff9b" />

<img width="3072" height="1664" alt="Image" src="https://github.com/user-attachments/assets/cfaf3110-594f-40c8-bc4b-03175449d75d" />

The current inline approach for playgrounds causes two issues:

1. **Inconsistency**: It breaks the unified design language of the admin panel.
2. **Clutter**: It permanently takes up vertical screen space for an administrative action that is performed very infrequently.

## Proposal

To align Code Playgrounds with our standard UI patterns, I propose moving the creation form out of the main view and into a modal dialogue.

**High-Level Approach:**
* Replace the current inline form with a standard `Add code playground` button above the data table (mirroring the Linkifiers page layout).
* Move the language, name, and URL template inputs into a standard Zulip modal using our existing `dialog_widget` architecture.

As Sahil noted in CZO since adding a playground is an admin-only action, requiring one extra click to open a modal is an ideal tradeoff to achieve a much cleaner, unified settings view.
